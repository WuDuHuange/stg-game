# STG 机娘游戏 · 重构设计文档（v0.2）

> 性质：游戏设计文档（GDD）+ 技术架构设计 合订本
> 目标：把当前「能跑通的 demo」重构为「真正能玩、好玩」的纵向卷轴弹幕射击游戏
> 定位方向（已与需求方对齐）：
> - 核心玩法 = 纵向卷轴射击（雷电 / 斑鸠式）
> - 画面 = 引入精灵图 / 机娘立绘
> - 流程 = 扩充主线战役 + 无尽模式（周目难度递进）
> - 深度 = 弹幕回避与走位为本核，Build 为辅助
> - 交付 = 先出文档评审，通过后再实现

## 0. 现状诊断：为什么现在是「demo」

对 `src/` 全量盘点的结论，按严重度归类：

### 0.1 玩法核心缺失（最致命）
| 问题 | 位置 | 影响 |
|------|------|------|
| 自机只有单发直线子弹，无武器弹幕 | `GameScene.shoot()` L753 | 战斗无爽感、无成长反馈 |
| 玩家是「血条+护盾」数值式生存，非 STG 残机系统 | `PlayerManager` / `GameScene` | 缺判定点、擦弹、残机、Bomb 等 STG 本核 |
| 敌人弹幕极少（单发/3~5 发扇形） | `GameScene.fire*Bullets()` | 没有弹幕美学与回避乐趣 |
| 「机娘」仅存在于标题，玩家/敌人全是 `Arc` 圆 | `createPlayer()` / `spawnWaveEnemy()` | 主题空壳 |

### 0.2 系统架构断裂
- 大量系统「实现但未接线」：`InputManager`、`ResourceManager`、`GameManager`、`GameStateManager`、`core/SceneManager`、`WeaponEnhancementManager`、`SkillEnhancementManager`、`DebugTools`（见 `docs/issues.md` L212-231）。
- `GameScene` 是 1000+ 行的「上帝类」，承担了渲染、输入、碰撞、波次、弹幕、UI 协调、经验成长全部职责。
- 数据层重复定义：`EnemyConfigs.ts` / `LevelConfigs.ts` / `EnemyData.ts` 存在多套枚举与接口（历史已修复部分，仍脆弱）。
- 技能/武器数据硬编码在 `SkillManager.loadExampleSkills()` / `WeaponLoader.createExampleWeapons()`，不可配置、不可扩展。

### 0.3 体验性问题
- 已确认 Bug：`SettingsUI.createSettingsInterface()` 中背景矩形 `bg` 最后才加入容器，遮挡了标签页与内容（渲染层级错误）。
- 关卡片段静态、只有 5 关、Boss 仅有 2 个且阶段切换弱。
- 无存档 / 解锁 / 排行榜，通关即结束，无重玩动力。

## 1. 设计目标与核心支柱

### 1.1 一句话体验
> 玩家的机娘在**密集而可读的弹幕**中穿梭、擦弹蓄力、反击清版，击败多阶段 Boss，逐步解锁更强机体与难度——以「回避」为主旋律的爽快竖版 STG。

### 1.2 四条核心支柱（决策都以此为判据）
1. **回避优先**：乐趣来自「看清弹幕 → 走位 → 极限擦弹」的正反馈，而非数值碾压。
2. **公平可读**：威胁可见、判定清晰、弹幕有预习（预警/节奏），死因可复盘。
3. **机娘魅力**：机体与立绘是世界观与解锁的核心动力。
4. **构筑是调味**：装备/技能提供节奏调剂与差异化，但不喧宾夺主。

### 1.3 借鉴与差异
- 借鉴：雷电（自机强化 + 副武器）、斑鸠（弹幕设计 + 黑白弹反）、东方（擦弹 / 符卡 / Boss 阶段演出）。
- 差异：以「机娘 + 轻构筑」营造差异化，弹幕密度低于硬核东方，更接近斑鸠的商业化爽感。

## 2. 核心玩法设计

### 2.1 宏观循环
```
局内：移动躲避 → 射击清版 → 擦弹蓄能 → 局内三选一成长 → 击败 Boss → 推进
局间：通关结算 → 解锁机娘/装备/难度 → 选择下一关或无尽 → 重开强化
```

### 2.2 自机系统（STG 本核，替代现有血条+护盾）

| 概念 | 设计 | 建议数值 |
|------|------|----------|
| 判定点 Hitbox | 机体中央一点，远小于机体视觉 | 半径 3px（机体约 24px） |
| 残机 Life | 中弹损伤判定点即 -1 生命，生命归 0 损 1 残机 | 生命 3，残机 3 |
| 短暂无敌 | 中弹后 1.5s 无敌 + 闪烁 | 1.5s |
| 护盾 Shield | 保留为「可吸收一次中弹」的稀有资源（替代原血条式护盾） | 可有可无，道具获得 |
| 擦弹 Graze | 敌弹进入判定点周围 0~10px 但未命中，计数 +1 | 判定环 10px |
| 精确走位 Focus | 按住 Shift 移动速度降至 40%，判定点高亮，便于微调 | 常速 300 / Focus 120 |
| 自机强化 Power | 拾取道具提升主炮/副炮火力等级 | 0~5 级 |

> **决策**：放弃「血条 + 缓慢恢复护盾」的 RPG 式生存，改为 STG 标准的「判定点中弹扣命」模型，这是「好玩」的第一前提。生命/残机可在设置中提供「新手模式（血条制）」降低门槛。

### 2.3 射击与 Bomb

- **主炮 Main Shot**：默认连射（按住 Space 持续），直上弹幕；随 Power 等级扩展弹道（直线 → 双列 → 扇形）。
- **副炮 / 子机 Option**：跟随自机的卫星，提供附加火力与阵型（直线 / 交叉 / 环绕）。
- **Bomb / 符卡**：清屏 + 全屏伤害 + 数秒无敌，消耗 Bomb 槽（残机数相关），是「破局」手段而非数值输出。
- **反馈**：命中打击感（闪光、停顿、震屏）、连击计数（Combo）驱动分数倍率。

### 2.4 弹幕与敌人

**弹幕谱面引擎（数据驱动）** 是本次重构的核心新增能力：

弹幕类型（单一 + 可组合）：
- `aimed` 指向自机、`spread` 扇形、`ring` 圆环、`spiral` 螺旋、`random` 随机、`laser` 激光（连续判定）、`curved` 曲线（加速/减速/正弦）。
- 发射器参数：位置、角度、速度、数量、间隔、持续时间、相位、曲线函数。

敌人分级：
- **杂兵 Popcorn**：清版节奏，少量直弹，压上来制造走位压力。
- **道中精英 Midboss**：小高潮，1~2 个符卡式弹幕。
- **Boss**：3~5 个阶段（Phase），每个阶段绑定一套弹幕 + 非攻击间隔（宣言演出）；血量低于阈值切换。

弹幕可读性规则：
- 敌弹统一为高对比暖色 + 光晕，自机弹为冷色，避免混淆；弹幕发射前有短暂预警（闪烁/预警线）。

### 2.5 Boss 战设计
- 每个 Boss = `阶段表`，含：进入血量阈值、机动模式、弹幕谱面引用、攻击/休整节奏。
- 血条铺顶（专用 Boss 血条），阶段切换时全屏宣言（「符卡名」演出）。
- 击败结算：分数 × Boss 奖励、解锁下一阶段剧情。

### 2.6 关卡与无尽
- **主线战役**：12 关 / 4 章（每章 3 关，末关 Boss）。保留并扩充现有 `LevelConfigs`，改为数据驱动 + 难度缩放表。
- **无尽模式 Rush**：通关主线后解锁；随机敌人组合，难度随波次/时间指数递增，排行榜记录生存波次与分数。
- **难度系统**：Easy / Normal / Hard / Lunatic 四档，通过「弹幕密度、速度、敌人血量」等系数整体缩放（见 §7 配置）。

### 2.7 构筑（轻量，服务回避主题）
- **局内三选一**（升级时）：主炮强化 / 副炮形态 / 被动（擦弹奖励提升、移动加速、Bomb+1 等）。
- **局间永久**：通关解锁机娘（不同判定点/机体性能）、装备（轻量数值差异）、难度。
- 携程装备系统「5 槽位」简化为「机体 + 2 装备」的轻构筑，避免数值膨胀破坏回避乐趣。

## 5. 技术架构重构

保留现有目录分层，但**明确职责、消除重复、数据驱动**：

```
src/
├── core/        # 应用生命周期：GameManager（启动）、GameStateManager（状态机）、TimeManager
├── systems/     # 跨场景服务：InputManager、AudioManager、ResourceManager（真加载）
├── game/        # 运行时玩法系统（数据驱动、与渲染解耦）
│   ├── player/     # 自机：判定点、擦弹、残机、Power、Bomb
│   ├── bullet/     # 弹幕引擎：BulletPattern、BulletEmitter、Laser
│   ├── enemy/      # 敌人：EnemyEntity、EnemyAI、BossController（阶段状态机）
│   ├── level/      # 关卡：LevelController、WaveSpawner、RushController
│   └── build/      # 构筑：装备/技能/被动（轻量）
├── ui/          # 表现层：HUD、Boss 血条、宣言、选关、结算、设置
├── scenes/      # 薄场景：Boot/Menu/Game/Pause/Result，仅做装配编排
├── data/        # 纯数据：武器/技能/敌人/关卡/弹幕谱面/难度表（无逻辑）
└── utils/       # Logger、对象池、数学工具、DebugTools（接线）
```

### 5.1 关键重构动作
1. **拆分上帝类**：`GameScene` 只做「装配 + 主循环调度」，玩法下沉到 `game/` 各系统。
2. **数据驱动**：武器、技能、敌人、关卡、弹幕谱面全部迁移到 `data/` 配置（TS 模块或 JSON），删除硬编码 `loadExampleSkills()` / `createExampleWeapons()`。
3. **渲染解耦**：逻辑实体（自机、敌人、子弹）与 Phaser 显示对象分离，便于对象池与测试。
4. **接线闲置系统**：启用 `InputManager` / `ResourceManager` / `GameStateManager` / `DebugTools`；废弃重复定义（统一到 `data/EnemyData.ts` 的枚举）。
5. **对象池**：子弹、敌人、粒子均用对象池（弹幕游戏对象海量，性能关键）。
6. **修复已知 Bug**：`SettingsUI` 渲染层级（背景先入容器，再叠内容）。
7. **测试**：为弹幕引擎、Boss 阶段机、碰撞/判定点、配置加载补 Vitest 单测。

### 5.2 状态机
```
BOOT → MENU → [SELECT] → PLAYING ⇄ PAUSED → RESULT → MENU
                        ↗ LEVEL_CLEAR / BOSS_DEFEAT / PLAYER_DEAD
```
由 `GameStateManager` 统一驱动，UI 层级基于状态而非当前的 `UILayerLevel` 枚举堆叠。

## 9. 验收标准（Definition of Done）
- 一局中玩家需「读弹幕 + 走位 + 擦弹」才能存活，而非站桩输出。
- Boss 战有明确阶段切换与符卡演出，死因可复盘。
- 弹幕密度/速度可读、敌我弹幕色彩严格区分。
- 所有玩法数据可配置（不硬编码），关键逻辑有单测覆盖。
- 无尽模式提供重玩动力与排行榜。

## 10. 已确认决策（评审结论）
1. **屏幕方向**：保持 1280×720 横屏，游戏区纵向卷轴（斑鸠家用版式），左右留白放 HUD。
2. **美术资源**：由开发侧工具生成程序化/占位美术（明显优于现有圆形），同步建立资源加载管线与《美术资源清单》，后续用户替换文件即生效。
3. **回避硬核度**：Normal 起全难度采用「判定点 + 残机 + 擦弹」纯 STG 制；Easy 提供血条制降级。
4. **构筑深度**：装备系统精简为「机体 + 2 装备」轻量构筑。
5. **排行榜**：localStorage 本地排行榜，接口层抽象，预留后端接入。
